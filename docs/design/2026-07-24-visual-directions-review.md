# UI/UX Pro Max 시각 방향 검수

작성일: 2026-07-24  
기준 구조: A안, 보드 중심 혼합형  
상태: 사용자 방향 선택 대기

## 방향 비교

| 방향 | 핵심 구조 | 강점 | 주요 위험 | 제품 적합성 |
|---|---|---|---|---|
| 맵 캔버스 | 지도 + 3단계 후보 바텀시트 | 핀과 카드 연결이 가장 직접적 | 제스처 충돌, 상태 복잡도 | 높음 |
| 카드 스튜디오 | 카드 목록 + 선택적 지도 | 친근함, 댓글·좋아요, 접근성 | 지도-목록 동시 연결 약화 | 보통 |
| 듀얼 윈도우 | 모바일 탭, 데스크톱 50:50 | 명확한 구조와 확장성 | 모바일 전환 피로, 도구적 인상 | 보통 |

## 오케스트레이터 권고

**맵 캔버스의 구조에 카드 스튜디오의 따뜻한 협업 톤을 결합한 방향**을 권고한다.

### 유지할 요소

- 모바일에서 지도와 후보 목록을 같은 화면에 유지
- 핀 선택과 카드 선택을 양방향으로 동기화
- 후보 목록은 중간·확장 상태를 가진 바텀시트로 표현
- 데스크톱은 지도와 후보 패널을 동시에 표시
- 장소 추가는 항상 보이는 주 행동
- 지역 찾기는 장소 추가보다 한 단계 낮은 보조 행동
- 좋아요·댓글이 잘 읽히는 따뜻한 카드 구성

### 조정할 요소

- 지도 비중을 고정 70%로 두지 않고 화면 높이와 시트 상태에 따라 조절
- 바텀시트는 닫힘 상태에서도 최소 한 후보 또는 빈 상태 행동이 보이게 함
- 코스 순서로 오해할 수 있는 숫자 핀은 사용하지 않음
- “아직 정해지지 않았어요” 대신 “지금 고른 곳이 없어요”처럼 확정을 암시하지 않는 문구 사용
- 민트·라임이 지도 위에서 충분한 명도 대비를 갖는지 검증
- 하트 색상만으로 좋아요 상태를 구분하지 않고 아이콘 채움과 텍스트를 함께 사용

## 다음 승인 단위

사용자가 방향을 선택하면 Claude UI/UX Pro Max에 다음 네 개의 저충실도 프레임만 먼저 요청한다.

1. 모바일 후보 보드 — 후보 있음
2. 모바일 후보 보드 — 빈 화면
3. 모바일 장소 상세 바텀시트
4. 모바일 탐색 지역·주변 장소 화면

이 네 프레임에서 정보 위계와 상호작용을 승인한 뒤 색상·타이포·컴포넌트 토큰과 전체 상태 화면으로 확장한다.
