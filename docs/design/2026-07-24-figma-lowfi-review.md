- Figma 파일: [감옥에서누가돌아왔게](https://www.figma.com/design/1u6oPaAOWLU26s6r5HwmwK/%EA%B0%90%EC%98%A5%EC%97%90%EC%84%9C%EB%88%84%EA%B0%80%EB%8F%8C%EC%95%84%EC%99%94%EA%B2%8C?node-id=395-396)
- 페이지: `개발 전용`
- 섹션: `MVP Candidate Board · Lo-fi`
- 디자인 방향: Map Canvas의 지도·목록 연결 구조와 Card Studio의 친근한 협업 분위기를 결합

## 승인 단위

이번 시안은 색상과 그래픽 완성도를 검토하는 단계가 아니라, 핵심 정보 구조와 상호작용 우선순위를 승인하기 위한 로우파이 시안이다.

| 화면 | Figma 노드 | 주요 검토 항목 |
| --- | --- | --- |
| 후보 보드 · 후보 있음 | `400:396` | 지도 핀과 후보 카드 대응, 현재 선택 장소, 장소 추가와 지역 찾기 |
| 후보 보드 · 빈 화면 | `401:402` | 첫 후보 추가 유도, 지역 찾기 보조 동선 |
| 장소 상세 시트 | `402:404` | 좋아요, 댓글, 현재 선택 변경, 외부 지도 링크 |
| 탐색 지역 · 주변 장소 | `403:406` | 제안 기준점과 임의 좌표 선택, 카테고리 탐색, 후보 추가 전 검색 결과 구분 |

## 공통 기반

- 모바일 기준 화면 크기: `390 × 844`
- 글꼴: `Noto Sans KR`
- 로컬 디자인 토큰: 색상, 간격, 모서리 반경
- 로컬 컴포넌트: 기본/보조 버튼, 기본/선택 후보 카드
- 현재 선택은 확정 상태가 아니라 `지금 여기 어때요?`라는 가벼운 제안 상태로 표현
- 초대 링크와 참여 코드 접근은 보드 헤더의 `초대 · 코드`에서 제공

### 브랜드 색상

| 역할 | 값 | 적용 |
| --- | --- | --- |
| 기본 강조색 | `#3568E7` | 주요 행동 버튼, 선택 핀, 강조 텍스트와 테두리 |
| 상태 배경색 | `#4675D9` / 18% | 현재 선택 배너, 선택 후보 카드, 안내 영역 |
| 보조 텍스트 | `#737373` | 메타 정보와 보조 설명 |
| 기본 텍스트 | `#333333` | 제목과 본문 |

주요 행동과 현재 상태가 혼동되지 않도록 주요 버튼은 기본 강조색을 사용하고, 선택·안내 상태는 18% 상태 배경색을 사용한다.

## 제품 가드레일

- 개설자를 포함한 모든 참여자의 권한은 동일하다.
- 현재 선택은 정식 투표나 최종 확정이 아니다.
- 지역 제안은 정답이 아니라 탐색 기준점이다.
- 사용자는 지도에 임의 좌표를 직접 찍어 주변을 탐색할 수 있다.
- 검색 결과는 후보에 추가하기 전까지 보드 후보가 아니다.
- 코스, 번호 지도, 확정 일정, 출발 안내, 공개 공유 페이지와 자체 별점은 만들지 않는다.

## 외부 API 역할

- Kakao Maps JavaScript SDK: 지도, 핀, 직접 좌표 선택
- Kakao Local API: 장소·주소 검색, 역지오코딩, 카테고리 주변 탐색
- ODsay API: 참여자 출발지 기준 도달 가능 영역
- TMAP과 지도 자동 검색: 현재 MVP 탐색 흐름에서 사용하지 않음
- 허용된 네이버·카카오 외부 장소 링크는 후보 출처 링크로 저장 가능

## 검증 결과

- 4개 화면 간 겹침 없음
- 빈 텍스트 레이어 없음
- 투표, 코스, 번호 지도, 확정 일정, 출발 안내, 공개 공유 기능으로 이어지는 행동 요소 없음
- 지역 제안을 정답이나 공정한 중간 지점으로 표현하지 않음
- 주변 검색 결과가 후보에 자동 등록되는 것처럼 표현하지 않음

## 다음 단계

정보 구조 승인 후 Claude UI/UX Pro Max에 다음 작업을 위임한다.

1. 승인된 로우파이 구조를 유지한 비주얼 방향 구체화
2. 기본, 로딩, 빈 화면, 오류, 선택 상태 확장
3. 모바일·데스크톱 반응형 화면 설계
4. 디자인 토큰과 재사용 컴포넌트 정리
5. 구현 인계에 필요한 상태·동작 주석 작성

React 퍼블리싱은 전체 Figma 디자인이 승인된 이후 시작한다.

## 인터랙션 스토리보드

정적 로우파이만으로 클릭 결과를 이해하기 어렵다는 피드백에 따라 기존 섹션을 유지하고 독립 프레임을 추가했다.

- 프레임: `Interaction Storyboard · Tap → Result`
- Figma 노드: `414:406`
- 크기: `2400 × 1780`
- 구성: 모바일 상태 7개, 행동·결과 연결선 7개
- 설계 기준: One thing per state, Tap → Result, Context-based feedback

포함된 상태:

1. 후보 보드 기본 상태
2. 지도 핀 탭 후 대응 카드 자동 이동·강조
3. 후보 카드 탭 후 장소 상세 바텀시트
4. 좋아요와 현재 선택의 보드 전체 반영
5. 장소 추가 검색·지도 선택 시트
6. 탐색 기준점 주변 검색과 후보 추가
7. 초대 링크·참여 코드 확인 시트

연결선은 이동 방향만 보여주지 않고 `사용자 행동 → 즉시 보이는 결과`를 한 문장으로 설명한다.

## Pure Minimalist 편집형 시안

이전 색상 방향과 Claude 산출물을 사용하지 않고 `minimalist-ui` 스킬만 적용한 독립 프레임을 추가했다.

- 프레임: `Editorial Interaction Guide · Pure Minimalist`
- Figma 노드: `423:406`
- 크기: `1800 × 2040`
- 위치: 기존 프레임 오른쪽의 독립 영역
- 글꼴: Instrument Serif, Geist, Geist Mono
- 팔레트: Warm Bone, White, Charcoal, Muted Gray, Pale Blue·Green·Yellow·Red
- 스타일: 1px 경계, 최대 12px 반경, 무그라디언트, 무그림자, 검정 주요 CTA

세 개의 편집형 챕터:

1. `핀에서 장소로`: 핀 탭 전후와 후보 카드 자동 연결
2. `탐색에서 후보로`: 주변 검색 결과와 후보 추가 후 보드 반영
3. `초대에서 대화로`: 초대·코드 시트와 복사 완료 피드백

각 챕터는 `제품 원칙 → 이전 화면 → 탭 → 이후 화면 → 즉시 피드백` 순서로 읽힌다.
