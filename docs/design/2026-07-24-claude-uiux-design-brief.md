# 후보 장소 보드 UI/UX 디자인 브리프

작성일: 2026-07-24  
디자인 담당: Claude UI/UX Pro Max  
제품·계약 검수 담당: 주 오케스트레이터  
현재 단계: 시각 디자인 방향 2~3개 제안

## 1. 요청 사항

모바일 우선 후보 장소 협업 보드의 시각 디자인 방향을 3개 제안한다. 아직 전체 화면을 제작하지 않는다. 각 방향은 같은 제품 구조와 기능 범위를 유지하되, 지도와 후보 목록을 연결하는 방식, 협업 감정, 정보 밀도에서 분명한 차이를 보여야 한다.

각 방향마다 다음을 제공한다.

1. 방향 이름과 한 문장 콘셉트
2. 핵심 감정과 사용 상황
3. 모바일 후보 보드의 화면 구성
4. 지도와 후보 카드의 대응 방식
5. 현재 선택 장소를 가볍게 표현하는 방법
6. 장소 추가와 지역 찾기의 우선순위 표현
7. 색상·타이포그래피·모서리·그림자·아이콘 방향
8. 데스크톱 확장 방식
9. 접근성과 구현상 주의점
10. 장점, 위험, 적합한 이유

가능하면 각 방향의 핵심 보드 화면을 저충실도 또는 중간 충실도 프레임으로 비교할 수 있게 제안한다.

## 2. 제품 정의

여러 사람이 하나의 약속 보드에 가고 싶은 장소를 모으고, 지도 핀·좋아요·댓글로 비교한 뒤 현재 선택된 장소를 함께 확인하는 모바일 우선 웹 서비스다.

핵심 가치는 장소 추천 결과가 아니라 여러 사람이 후보를 함께 축적하고 비교하는 과정이다.

서비스는 행정 지도나 경로 최적화 도구보다 친구들과 약속 장소를 모으는 가볍고 친근한 협업 보드에 가깝다.

## 3. 확정된 정보 구조

선택된 구조는 **보드 중심 혼합형**이다.

### 독립 경로

```text
/
/boards/new
/join/:inviteCode
/boards/:boardId
/boards/:boardId/explore
```

### 보드 내부 바텀시트·모달

- 참여 코드·초대 링크 공유
- 참여자 목록과 본인 출발지
- 장소 추가: 장소 검색, 외부 출처, 지도 직접 핀
- 장소 상세: 좋아요, 댓글, 현재 선택, 외부 지도, 삭제
- 현재 선택 변경·해제 확인

### 별도 탐색 화면

- 만나기 좋은 지역 제안 준비·진행·결과
- 제안된 기준점 선택
- 지도 임의 좌표 선택
- 기준점 또는 임의 좌표 주변 카테고리·키워드 검색
- 검색 결과를 후보 보드에 추가

## 4. 핵심 사용자 흐름

1. 홈에서 보드를 만들거나 초대 코드·링크로 입장한다.
2. 닉네임을 입력하고 출발지를 지금 등록하거나 나중에 설정한다.
3. 후보 보드에서 지도 핀과 후보 카드를 함께 본다.
4. 검색, 외부 출처, 직접 핀으로 후보를 추가한다.
5. 후보 상세에서 좋아요와 댓글을 남긴다.
6. 누구나 현재 선택 장소를 지정·변경·해제한다.
7. 후보가 막히면 탐색 지역을 요청한다.
8. 제안 기준점 또는 임의 좌표 주변을 카테고리·키워드로 탐색한다.
9. 검색 결과를 후보로 추가하고 보드로 돌아온다.

## 5. 모바일 핵심 화면: 후보 장소 보드

이 화면이 전체 디자인의 기준이다.

필수 요소:

- 보드 이름
- 현재 선택 장소 요약 또는 선택 없음 상태
- 참여자 정보 진입
- 참여 코드·초대 링크 진입
- 모든 후보가 보이는 지도와 핀
- 지도 핀과 대응하는 후보 카드 목록
- 카드의 장소명, 카테고리, 제안자, 좋아요 수, 댓글 수
- 선택된 카드·핀의 동일한 시각 강조
- 항상 찾기 쉬운 장소 추가 행동
- 후보가 없을 때 장소 추가와 지역 찾기
- 후보가 있을 때도 지역 찾기로 진입 가능한 보조 행동

### 지도 원칙

- 지도는 중심 정보지만 화면 전체를 복잡하게 지배하지 않는다.
- 모바일에서는 지도와 후보 목록 사이의 연결이 명확해야 한다.
- 핀 선택 시 대응 카드가 보이고, 카드 선택 시 대응 핀이 강조돼야 한다.
- 데스크톱에서는 지도와 후보 패널을 좌우로 동시에 보여 줄 수 있어야 한다.

### 현재 선택 원칙

- ‘확정’, ‘결정 완료’, ‘최종 장소’라는 표현을 사용하지 않는다.
- “지금 여기 어때요?”에 가까운 가벼운 포인터로 표현한다.
- 선택한 사람과 변경 시각을 과도하지 않게 확인할 수 있어야 한다.
- 누구나 지정·변경·해제할 수 있다는 인상을 줘야 한다.
- 선택이 없는 상태도 자연스러워야 한다.

## 6. 장소 상세 시트

필수 요소:

- 장소명, 주소, 카테고리
- 저장된 외부 지도 링크 열기
- 좋아요 추가·취소와 현재 수
- 댓글 목록과 댓글 작성
- 본인 댓글 삭제
- 현재 선택 지정·변경·해제
- 후보 삭제

삭제는 모든 참여자가 할 수 있다. 선택된 후보를 삭제하면 현재 선택이 자동 해제된다는 안내가 필요하다.

## 7. 장소 추가 시트

세 가지 방식이 동등한 후보 유입 경로다.

1. 장소명·지역명 검색
2. 외부 지도에서 확인한 장소 정보 입력
3. 지도에서 직접 좌표 선택

검색 결과는 사용자가 명시적으로 추가하기 전까지 후보가 아니다. 직접 핀과 외부 출처도 장소명과 좌표 확인이 필요하다. 좌표 없는 링크만으로는 후보를 만들 수 없다.

## 8. 탐색 지역·주변 장소 화면

지역 제안은 공정한 중간 지점이나 최적 장소 추천이 아니다. 어디에서 찾을지 감이 없을 때 사용하는 탐색 기준점이다.

필수 상태:

- 참여자 출발지 등록 상태
- 본인 출발지 설정 진입
- 허용 시간 30·45·60분
- 작업 대기·실행
- 기준점 1~3개
- 성공했지만 공통 영역 또는 기준점이 없는 상태
- 외부 API 실패·요청 과다·재시도
- 제안 기준점 선택
- 지도 임의 좌표 선택
- 카테고리·키워드 주변 탐색
- 검색 결과를 후보로 추가

다른 참여자의 출발지 상세 주소와 좌표는 보여 주지 않고 등록 여부만 보여 준다.

## 9. 권한과 협업 원칙

- 개설자는 보드를 만들었다는 이력만 다르고 다른 참여자와 권한이 같다.
- 모든 참여자가 후보 추가·삭제, 좋아요, 현재 선택 변경, 지역 제안, 초대 정보 확인을 할 수 있다.
- 댓글 삭제는 작성자만 가능하다.
- 한 참여자는 여러 장소에 각각 좋아요를 남길 수 있다.
- 호스트 전용 배지·관리자 메뉴·왕관 아이콘으로 권한 차이를 암시하지 않는다.

## 10. 범위 제외

다음 개념을 화면, 문구, 아이콘, 상태에 넣지 않는다.

- 정식 투표·마감·득표
- 코스와 방문 순서
- 번호 지도
- 장소 또는 일정 확정
- 출발 시간·길찾기 안내
- 공개 공유 페이지
- 운영 대시보드
- 장소 자체 별점·리뷰·인기도 점수
- 공정성 점수·최적 중간 지점
- TMAP 기반 이동시간 비교

## 11. 필수 상태

모든 핵심 화면은 다음 상태를 고려한다.

- 기본
- 최초 로딩
- 부분 로딩
- 빈 화면
- 입력 검증 오류
- 네트워크 오류와 재시도
- 참여 토큰 오류
- 찾을 수 없는 보드·장소
- 선택됨·선택 없음
- 등록·저장 중
- 성공 피드백

## 12. 반응형 기준

- 최소 360px 모바일부터 지원한다.
- 모바일 터치 대상은 충분한 크기와 간격을 가진다.
- 지도 위 컨트롤이 후보 핀과 주요 행동을 가리지 않는다.
- 모바일 바텀시트는 닫힘·중간·확장 상태가 필요할 수 있다.
- 데스크톱은 지도와 목록·상세 패널을 동시에 보여 주되 모바일과 정보 구조를 공유한다.

## 13. 접근성

- 색상만으로 핀·카드·현재 선택 상태를 구분하지 않는다.
- 지도 없이도 후보 목록으로 핵심 기능을 수행할 수 있어야 한다.
- 포커스 상태와 키보드 탐색을 고려한다.
- 아이콘 단독 버튼에는 이름이 필요하다.
- 오류 메시지는 문제와 다음 행동을 함께 설명한다.
- 움직임 감소 설정을 존중할 수 있는 전환을 제안한다.

## 14. 기술 제약

- React 19, JSX, Vite 8, Tailwind CSS 4
- 현재 React Router 없음
- 신규 의존성은 별도 승인 필요
- Kakao Maps JavaScript SDK는 지도 표시·핀·좌표 선택에 사용
- Kakao Local REST, ODsay는 백엔드를 통해 사용
- 모바일 시트와 데스크톱 패널을 같은 컴포넌트 개념으로 구현할 수 있어야 함

## 15. 이번 산출물의 승인 기준

시각 방향 제안은 다음 질문에 답해야 한다.

1. 후보 보드가 제품의 중심으로 느껴지는가?
2. 지도와 카드의 대응이 즉시 이해되는가?
3. 장소 추가가 가장 쉽게 발견되는가?
4. 좋아요·댓글·현재 선택이 서로 다른 의미로 보이는가?
5. 현재 선택이 확정처럼 무겁게 보이지 않는가?
6. 지역 찾기가 결과 추천이 아닌 보조 탐색으로 보이는가?
7. 친구들과 쓰는 친근한 협업 서비스로 느껴지는가?
8. 360px 모바일과 데스크톱으로 확장 가능한가?

## 16. 금지 사항

- 전체 화면 제작을 바로 시작하지 않는다.
- 시각 방향 승인 전 디자인 시스템을 확정하지 않는다.
- 명세에 없는 기능을 추가하지 않는다.
- 기존 와이어프레임의 화면 번호와 UI를 디자인 기준으로 삼지 않는다.
- 예쁜 지도 화면만 만들고 후보 비교·협업 행동을 약화하지 않는다.
